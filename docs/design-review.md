# 工位界面设计复核

2026-11-24，用户指出首版“陪伴设置”太死板，并要求参考 Antigravity 中的 Opus 或 Gemini Neon。通过本机 Antigravity 分别向 **Gemini 4 Neon Medium** 与 **Claude Opus 5.5 Medium** 咨询，均已收到回复；两次咨询只要求设计意见，没有让外部模型改动项目文件。

## 共同结论与采用方式

首版的“左侧角色、右侧编号表单”仍像管理后台。新版把首页改成一个完整的工位场景：窗景、台灯、少量工程用品和一块能站稳角色的桌面；真实精灵角色在场景上独立绘制。首页只呈现当前状态、简短的闲置规则和常用动作，分钟输入、大小、速度、显示器及系统开关收入右侧设置抽屉。

Neon 提出单场景主界面、低频参数抽屉和克制动效。Opus 进一步将信息简化为三层：角色与环境、真实状态、桌沿下方动作栏；建议让工程笔记或便签成为设置入口，同时保留常规设置按钮以便发现。

采用原生 `dialog` 做抽屉，支持键盘焦点、Escape 和关闭后的焦点恢复。所有操作仍走已有主进程接口；巡逻状态、方向、位置和设置来自实际桌宠。挥手和小跳在当前状态允许且主进程确认后播放，不显示虚构的聊天、情绪数值或工作记录。

## 没有采用的建议

- 现有素材没有趴睡、坐姿、打哈欠、揉眼、独立光环旋转等动画，不能仅换文案就宣称实现。
- 八方向注视是离散素材，不冒充连续瞳孔追踪。
- 不采用霓虹网格、荧光路线和粒子装饰；保留安静、略困的小工程师气质。
- 不把点击任意桌面位置或拖拽到画面角落解释成隐蔽命令，散步与回家使用明确按钮。
- 暂停只说明停止出发，不用“趴一会儿”等没有对应动作的描述；倒计时来自系统闲置读数，不生成虚假的定时出发承诺。

这些意见是本次界面重构的设计输入，最终实现和可用性以程序及验证记录为准。

## 0.1.1 成品复审

2026-11-24 继续评审，实际参与模型仍为 Antigravity 中的 **Gemini 4 Neon Medium** 与 **Claude Opus 5.5 Medium**。Neon 会话 `44f78eef-60c5-4ed8-8c0d-67f73ee24efa` 直接审查提供的前端源码；Opus 延续会话 `123b9868-7da7-4465-9a75-854e4aded26a`，读取真实首页、抽屉截图及项目源码。模型没有执行测试或修改仓库；实现、复现与测试由 Codex 完成。

Neon 第一轮指出五项交付问题：滑块拖出抽屉误关、聚焦中的屏幕选项重建后跳回默认、文字过小和颜色偏浅、最小窗口错误提示重叠、三位数闲置分钟输入过窄。对应修复增加了背景按下/松手配对判断、选择值保留、字体和对比度调整、顶部独立提示区与更宽的数字输入框。

Opus 的成品复审补充了启动时误显演示数据、标题与副文案状态来源不一致、操作说明和读屏语义、错误包装文字、不同窗口比例与 200% 缩放，以及暂停预览和桌宠呼吸不一致等问题。连接成功前锁定操作；所有状态展示使用统一优先级；便签承担散步规则，副文案只描述当前状态；持续存在的播报区域避免隐藏后无法播报。暂停停止巡游，但保留呼吸，明确请求的挥手与小跳仍可用。

角色脚底现在跟随背景图实际 `cover` 缩放和底部裁切。站位锚点是图像高度的 84%，位于桌面平面内部，并非墙面与桌面的后沿；用素材 `feetY=201` 扣除脚底透明留白。高缩放使用可纵向滚动的布局，保留完整场景与可达控件，不通过缩小字体塞入窗口。

并行运行审查还修复了保存回执覆盖正在编辑的草稿、跨字段错误被新保存掩盖、最小化后重播过期动作，以及便携版共享配置与安装版实际登录启动项不一致。登录项验证使用模拟接口，没有修改测试机器的实际启动项。

Neon 第二轮确认原五项问题已修复，同时指出 200% 缩放后滚到底部点击动作时，顶部提示会离开视口。最终把高缩放提示放到动作栏正上方，用 `ResizeObserver` 测量操作栏实际高度；补充两个小视口下每个动作和 60 字错误的完整可见性断言。重复提示先清空、再延迟更新播报，快速覆盖和离页时取消旧计时器。正常尺寸的顶部提示位置不变。

### 最终结论

- **Opus 第二轮**："满意，本次交付没有阻塞问题。" 依据两张真实更新截图和提供的完整 0.1.1 源码；未亲自运行项目，也未查看 200% 原生截图。
- **Neon 第三轮**："本次交付范围满意，没有剩余阻塞项。" 依据最终源码以及明确由 Codex 执行的测试证据；未亲自运行项目或查看截图。明确确认高缩放反馈可见性修复成立。

最终验证包括 22 项单元测试、真实 Electron 集成与 UI 回归、8 组窗口/缩放布局，以及打包 EXE 冒烟测试，详见 [验证记录](verification.md)。模型认可只覆盖本次桌宠和工位界面交付范围，不表示未测试的硬件组合也经过验收。少量未使用的旧样式保留为非阻塞清理项。
